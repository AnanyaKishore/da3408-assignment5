## Setup

Tested with Python 3.14 on a single Linux laptop (12th Gen Intel Core i7-1255U, 12 CPU cores, about 8 GB of RAM). Everything runs on the CPU. The Ray application is limited to 2 CPUs.

```bash
git clone https://github.com/AnanyaKishore/da3408-assignment5.git
cd da3408-assignment5
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python eta_data.py
python -c "import pandas as pd, eta_data; pd.read_csv('data/eta_fresh.csv')[eta_data.FEATURES].head(200).to_csv('data/eta_sample.csv', index=False)"
```

Ports used: 8000 (Part A), 5101 and 5102 (Part B), 8100 (Part C). Make sure they are free before starting (`ss -ltnp | grep -E ':8000|:5101|:5102|:8100'` should print nothing).

## Where to look

| File | Purpose |
|------|---------|
| `eta_data.py`, `load_test.py`, `requirements.txt` | Starter files, unchanged. `eta_data.py` generates the data and both model bundles. `load_test.py` is the closed-loop load generator. |
| `partA/eta_app.py` | FastAPI service. Loads the model once from `ETA_MODEL` (default `data/eta_v1.joblib`). `POST /v1/models/eta:predict` validates ranges, batch size (1 to 500) and the cross-field rule (`distance_km > 150` with `n_stops > 20` is rejected as infeasible). Every response carries `X-Request-ID`. Validation errors return a structured 422 body, inference errors a generic 500. `GET /metrics` serves a Prometheus counter and latency histogram, `GET /healthz` the model version. |
| `partA/test_eta_app.py` | 21 pytest cases with `TestClient`: valid request, batch order, invalid inputs, infeasible rule, batch limits, request-id echo and generation, metrics format and a monkeypatched 500. |
| `partA/loadtest_results.json` | Load test of v1 at concurrency 1, 2, 4, 8 and 16 (4 s each). |
| `partB/eta_mlflow.py` | `register()` logs both models as a custom pyfunc (columns `eta_minutes`, `model_version`) with a signature, an input example and pinned requirements, registers them as `eta-model` and sets the aliases `prod` (v1) and `candidate` (v2). `decide()` is the pure multi-criteria gate, `promotion_gate()` evaluates both aliases on fresh data, and `shadow` sends the same 200 requests to both MLflow servers. |
| `partB/test_gate.py` | 16 tests of `decide()` with synthetic numbers, including values just inside, at and just outside each threshold. |
| `partB/gate_output.txt`, `partB/shadow_output.txt` | Gate output with default thresholds and with `min_rel_gain=0.60`, and the shadow comparison. |
| `partC/eta_ray.py` | Ray Serve application. `EtaModel` replicas (0.25 CPU each): prod with 2 replicas, candidate autoscaling from 1 to 3. A FastAPI router sends a customer to the candidate when a SHA-256 hash of `customer_id` falls below the weight, or when the header `X-Beta: 1` is present. `build(weight, extra_work_ms)` returns the application. |
| `partC/verify_ray.py`, `partC/verify_output.txt` | Deploys the app on a 2-CPU Ray and checks, with assertions, the candidate share, stickiness, stickiness after a redeploy, no customer moving back when the weight rises, and the header override. |
| `partD/smoke_eta.py` | Release-gate smoke test with seven checks (health, version, three model-sanity checks, 422 on invalid input, p95 latency). Exits 0 on success and 1 on failure. |
| `Report_DA3408_Assignment5.pdf` | Tables, written answers, machine description and the list of what was not tested. |

# Running the assignment

Run every command from the repository root, with the virtual environment active (`source .venv/bin/activate`) in every terminal. Three terminals are used.

## Part A: REST service

```bash
# Terminal 2
pytest -q partA
```
Should report `21 passed`.

```bash
# Terminal 1
ETA_MODEL=data/eta_v1.joblib uvicorn eta_app:app --app-dir partA --port 8000
```
Check http://localhost:8000/healthz (`{"status":"ok","model_version":"v1"}`) and http://localhost:8000/metrics.

```bash
# Terminal 2: concurrency sweep (A3.1)
python load_test.py --url http://localhost:8000/v1/models/eta:predict --data data/eta_sample.csv \
    --concurrency 1 2 4 8 16 --duration 4 --out partA/loadtest_results.json

# Terminal 2: cost per row, batch 1 versus batch 100 (A3.3)
python load_test.py --url http://localhost:8000/v1/models/eta:predict --data data/eta_sample.csv --concurrency 1 --duration 4 --batch 1
python load_test.py --url http://localhost:8000/v1/models/eta:predict --data data/eta_sample.csv --concurrency 1 --duration 4 --batch 100
```

For the capacity change (A3.4), stop Terminal 1 with `Ctrl+C` and restart the service with two worker processes:
```bash
# Terminal 1
ETA_MODEL=data/eta_v1.joblib uvicorn eta_app:app --app-dir partA --port 8000 --workers 2
```
```bash
# Terminal 2
python load_test.py --url http://localhost:8000/v1/models/eta:predict --data data/eta_sample.csv \
    --concurrency 1 2 4 8 16 --duration 4
```
Then stop Terminal 1 with `Ctrl+C` and restart the single-worker service for Part D:
```bash
# Terminal 1
ETA_MODEL=data/eta_v1.joblib uvicorn eta_app:app --app-dir partA --port 8000
```

## Part D: smoke test (against the Part A service)

```bash
# Terminal 2
python partD/smoke_eta.py --url http://localhost:8000 --expect-version v1; echo "exit code: $?"
python partD/smoke_eta.py --url http://localhost:8000 --expect-version v2; echo "exit code: $?"
```
The first run passes 7 of 7 checks with exit code 0. The second fails the version check with exit code 1, which shows the gate blocking the wrong model. Then stop Terminal 1 with `Ctrl+C`.

## Part B: MLflow registry, gate and shadow

In each of the three terminals, first run:
```bash
export MLFLOW_TRACKING_URI=sqlite:///mlflow.db
```
```bash
# Terminal 2
pytest -q partB
rm -rf mlflow.db mlruns        # only for a clean registry (versions 1 and 2)
python partB/eta_mlflow.py register
python partB/eta_mlflow.py gate > partB/gate_output.txt
python partB/eta_mlflow.py gate --min-rel-gain 0.60 >> partB/gate_output.txt
cat partB/gate_output.txt
```
`pytest` should report `16 passed`. `register` prints the registry table (version 1 `prod` v1, version 2 `candidate` v2). The gate promotes v2 with the default thresholds and does not with `min_rel_gain=0.60`.

```bash
# Terminal 1
mlflow models serve -m "models:/eta-model@prod" -p 5101 --env-manager local
```
```bash
# Terminal 3
mlflow models serve -m "models:/eta-model@candidate" -p 5102 --env-manager local
```
Once both servers are listening:
```bash
# Terminal 2
python partB/eta_mlflow.py shadow > partB/shadow_output.txt
cat partB/shadow_output.txt
```
Then stop Terminals 1 and 3 with `Ctrl+C`.

## Part C: Ray Serve sticky canary

```bash
# Terminal 2
python partC/verify_ray.py > partC/verify_output.txt
cat partC/verify_output.txt
```
Starts Ray with 2 CPUs, deploys the application on port 8100, runs checks (a) to (e) and ends with `ALL CHECKS PASSED`. Ray is shut down at the end. The final `(raylet) ... graceful_shutdown` line is printed during shutdown and is harmless.

Optionally, the application can be kept running and checked with the smoke test:
```bash
# Terminal 1
python partC/eta_ray.py --weight 0.1
```
```bash
# Terminal 2
python partD/smoke_eta.py --url http://127.0.0.1:8100 --expect-version v2 --beta
```
